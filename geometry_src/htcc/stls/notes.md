# HTCC `stls/` CAD meshes

The three HTCC beamline cones are CAD rows in the separate SQLite `htcc_cad` system (see
[`../htcc.py`](../htcc.py) and `build_cad` in [`../geometry.py`](../geometry.py)). Keeping them in their own
system — rather than in the native `htcc` system — leaves the native geometry/material comparison against
clas12Tags clean at 537 rows. The `htcc_cad` system uses `factory: sqlite` (not the directory-based
`factory: CAD`): the CAD rows live in the same `gemc.sqlite` and gemc builds each `solid = CAD` row with the
per-volume CAD mesh builder, so no separate mesh directory is needed at load time.

The meshes are regenerated by [`../build_cad_meshes.py`](../build_cad_meshes.py), which needs `pymeshlab`,
so run it with the gemc-dev python environment (the one that also has `pygemc`):

```bash
/opt/jlab_software/<platform>/gemc/dev/python_env/bin/python3 ../build_cad_meshes.py          # rebuild
/opt/jlab_software/<platform>/gemc/dev/python_env/bin/python3 ../build_cad_meshes.py --report # topology
```

## Placement

GEMC2 authors the cones in `clas12Tags/geometry_source/htcc/cad/cad_<variation>.gxml`: all three are
daughters of `root`, material `rohacell31`, colour `888888`, rotation `0, 180, 0 deg`, placed at the
detector-survey z (the same global z-shift as the gas volume: default 0, rga_spring2018 -1.0 cm,
rga_fall2018 -1.94 cm). `htccMollerConeExt` is nudged +1 mm in z to avoid overlapping `htccMollerCone`.
`build_cad` reproduces these placements per variation. Verified with `gemc … -check_overlaps=2`: the three
cones report no overlap with each other or with the native HTCC volumes.

## Meshes

Each raw clas12Tags mesh is loaded by GEMC2 as-is (an uncured CADMesh tessellated solid). Here each is cured
into a watertight, coherently oriented, decimated G4-ready solid with `pygemc.utilities.cure_mesh`:

| mesh | raw facets | cured facets | notes |
|------|-----------:|-------------:|-------|
| `htccCone` | 18818 | 6000 | double-walled entry cone; decimated, watertight, manifold |
| `htccMollerCone` | 6232 | ~5900 | single-shell Moller cone; self-intersections removed |
| `htccMollerConeExt` | 1748 | 1748 | small double-walled extension; already light, cured only |

`htccCone` and `htccMollerConeExt` come out watertight (`boundary_edges = 0`) and fully manifold.

**`htccMollerCone` limitation.** The source mesh has ~180 non-manifold edges (internal self-touching walls).
Curing with self-intersection removal reduces these to ~42 while keeping the solid watertight and
shape-exact, and Geant4 loads it (one benign `G4TessellatedSolid::SetSolidClosed()` "wrong orientation"
warning, and no overlap). This is already better than the raw mesh GEMC2 uses. The defect cannot be fully
removed without distorting the shape: Poisson reconstruction produces a clean manifold but **inflates the
cone radius ~53 %** (125 → 191 mm) because it balloons the open-ended tube, and iterative non-manifold repair
either reopens the surface (loses watertightness) or re-creates non-manifold facets. The watertight,
shape-exact cured mesh is therefore preferred over a clean but wrong-sized one.
