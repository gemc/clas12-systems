# CLAS12 GEMC Systems 0.1

Initial development release for the GEMC3 CLAS12 systems repository.

## Release notes

This release establishes the CLAS12 systems repository as the GEMC3 companion to the core GEMC runtime in
`../src`, the Python geometry API in `../pygemc`, and the public documentation site in `../home`.

## Repository structure

- Added the top-level Meson build used to register CLAS12 detector systems.
- Added the system registry pattern through `clas12_systems`.
- Added per-system geometry tests that run `geometry_src/<system>/<system>.py` from the detector directory.
- Added the shared plugin registry model for future detector `.gplugin` shared libraries.
- Added CI support for deploy/test, sanitizers, CodeQL, Doxygen, development releases, and binary tarballs.

## Geometry systems

- Added the first GEMC3 CLAS12 geometry system: `dc`.
- Added a clean, executable `geometry_src/dc/dc.py` main script.
- Added `geometry_src/dc/geometry.py`, `materials.py`, and `variations.py`.
- Added `geometry_src/dc/factory.groovy` to run the coatjava DC geometry service locally.
- Added `geometry_src/dc/dc.yaml` as a ready-to-run GEMC steering card.
- Added the first GEMC3 CLAS12 system port: `geometry_src/dc`.
- Added a template-style executable `dc.py` entry point that runs from the detector directory and writes GEMC
  geometry through `pygemc.autogeometry`.
- Added local DC run and variation mapping in `geometry_src/dc/variations.py`.
- Added a local coatjava bridge for DC geometry generation through `factory.groovy`.
- Preserved CLAS12Tags ordered rotations in the generated DB instead of flattening them to plain x/y/z
  rotations.
- Marked DC volumes with `g4placement_type = "passive"` so GEMC uses the GEMC2/clas12Tags Geant4 placement
  convention for ported CLAS12 detector geometry.
- Expanded the repository README with scope, layout, GEMC3/pygemc/home relationships, build/test workflow,
  coatjava notes, plugin conventions, and validation guidance.
- Added `geometry_src/dc/plugin/` with `readoutSpecs.cc` and the `meson.build` registry entry — the DC
  plugin defines readout specs for the drift-chamber digitization routine.
- Installed CLAS12 plugins expose their directory through a generated `clas12-systems.pc` pkg-config file,
  enabling callers to locate plugins with
  `pkg-config --variable=plugindir clas12-systems`.

## DC plugin

- Added `definePluginOptions()` entry point to `geometry_src/dc/plugin/readoutSpecs.cc`. GEMC probes
  this symbol before options parsing when `dc` appears in a `gsystem` list, so DC-specific options are
  registered in the schema, appear in `gemc dc.yaml -h`, are saved to the configuration snapshot, and
  can be set from the command line or YAML alongside core options.
- Added the `dc_timeWindow` option (default 500 ns) declared in `definePluginOptions()` and read in
  `defineReadoutSpecsImpl()`, replacing the previously hardcoded value. Users can override the
  electronics integration window without recompiling: set `dc_timeWindow: 750.0` in the YAML steering
  card or pass `-dc_timeWindow=750.0` on the command line.
- Added `"dc"` as an independent verbosity key. `GOptions("dc")` in `definePluginOptions()` registers
  the key in the verbosity schema, and the `DC_digitization` constructor reassigns `log` to use the
  `"dc"` channel instead of the inherited `"gdigitization"` channel. Control DC plugin log output
  independently with `verbosity.dc: 2` (YAML) or `-verbosity.dc=2` (command line); the global
  `gdigitization` verbosity continues to control all other digitization plugins.

## HIPO output

- Added CLAS12 digitized-data publishing through the HIPO streamer plugin. ADC, TDC, and waveform banks are
  enabled from the digitization output variables present in each detector hit.
- Added schema-aware HIPO column writing for integer and floating-point output variables. The publisher now
  writes byte, short, int, long, float, and double columns through the type declared by the target HIPO schema
  instead of assuming one fixed C++ type per variable.
- Treated touchable identities as defaults only. Detector digitization plugins may override bank columns with
  explicitly published output variables when a schema column has detector-specific meaning, such as DC global
  layer `1..36` instead of the touchable-local layer.
- Supported both prefixed variables (`ADC_*`, `TDC_*`, `WF_*`) and direct schema-column variables. This lets a
  digitization plugin publish detector-specific bank fields without duplicating generic identity handling.

## HIPO histogram comparison

- Added the `hipo-histos` utility to read HIPO files, fill ROOT histograms, and write PNG summary plots. The
  first supported subsystem is `dc`, using `MC::True` and `DC::tdc`.
- Added DC summary plots with occupancy, r-vs-z, and z-vertex panels for regions R1, R2, and R3; TDC panels by
  region and sector; and a layer-wire occupancy map.
- Added two-file comparison mode with `--compare-system dc`, overlay PNGs, labels, event-count normalization
  for unequal input sizes, and optional ROOT interactive mode.
- Added diagnostic comparison output with per-histogram `passed` or `failed` status, chi2/ndf, relative integral
  difference, maximum bin difference, occupied-bin counts, and median entries per occupied bin.
- Added `--fail-on-diff` for CI use, plus configurable `--max-chi2-ndf`, `--max-integral-diff`,
  `--max-bin-diff`, and `--min-entries-per-bin` thresholds.
- Propagated ROOT bin errors into comparison plots and diagnostics. The chi2 calculation uses stored bin errors
  when available and falls back to an approximate two-sample Poisson variance for histograms without explicit
  errors.
- Computed DC z-vertex and occupancy-summary uncertainties from event-to-event fluctuations rather than
  individual hit counting errors, because DC hits from the same simulated event are correlated. This makes
  different-seed GEMC comparisons statistically meaningful for those projections.

## coatjava

- Added local coatjava installation support under `geometry_src`.
- Added CI helpers to install Java, Maven, git-lfs, and jq before coatjava setup.
- Kept coatjava local to this repository so CLAS12 systems can use Java geometry services without polluting the
  GEMC runtime repository.

## Compatibility notes

- CLAS12 detector geometry ported from GEMC2 should use `g4placement_type = "passive"` in `GVolume`.
- Ordered rotations from CLAS12Tags should remain ordered in the database, for example `ordered: yxz, ...`.
- The obsolete DC `original` variation is intentionally not supported by the GEMC3 DC port.

## Validation

- DC default geometry is expected to token-match
  `../clas12Tags/geometry_source/dc/dc__geometry_default.txt` for shared GEMC geometry fields.
- The default DC geometry run is `11`.
