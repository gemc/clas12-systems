# CLAS12 GEMC Systems 0.1

Initial development release for the GEMC3 CLAS12 systems repository.

## Release notes

This release establishes the CLAS12 systems repository as the GEMC3 companion to the core GEMC runtime in
`../src`, the Python geometry API in `../pygemc`, and the public documentation site in `../home`.

## Repository structure

- Added the top-level Meson build used to register CLAS12 detector systems.
- Added the system registry pattern through `clas12_systems`.
- Added per-system geometry tests that run `geometry_src/<system>/<system>.py` from the detector directory.
- Added the shared plugin registry model for future detector `.gplugin` shared libraries.
- Added CI support for deploy/test, sanitizers, CodeQL, Doxygen, development releases, and binary tarballs.

## Geometry systems

- Added the first GEMC3 CLAS12 geometry system: `dc`.
- Added a clean, executable `geometry_src/dc/dc.py` main script.
- Added `geometry_src/dc/geometry.py`, `materials.py`, and `variations.py`.
- Added `geometry_src/dc/factory.groovy` to run the coatjava DC geometry service locally.
- Added `geometry_src/dc/dc.yaml` as a ready-to-run GEMC steering card.
- Added the first GEMC3 CLAS12 system port: `geometry_src/dc`.
- Added a template-style executable `dc.py` entry point that runs from the detector directory and writes GEMC
  geometry through `pygemc.autogeometry`.
- Added local DC run and variation mapping in `geometry_src/dc/variations.py`.
- Added a local coatjava bridge for DC geometry generation through `factory.groovy`.
- Preserved CLAS12Tags ordered rotations in the generated DB instead of flattening them to plain x/y/z
  rotations.
- Marked DC volumes with `g4placement_type = "passive"` so GEMC uses the GEMC2/clas12Tags Geant4 placement
  convention for ported CLAS12 detector geometry.
- Expanded the repository README with scope, layout, GEMC3/pygemc/home relationships, build/test workflow,
  coatjava notes, plugin conventions, and validation guidance.
- Added `geometry_src/dc/plugin/` with `readoutSpecs.cc` and the `meson.build` registry entry — the DC
  plugin defines readout specs for the drift-chamber digitization routine.
- Installed CLAS12 plugins expose their directory through a generated `clas12-systems.pc` pkg-config file,
  enabling callers to locate plugins with
  `pkg-config --variable=plugindir clas12-systems`.

## coatjava

- Added local coatjava installation support under `geometry_src`.
- Added CI helpers to install Java, Maven, git-lfs, and jq before coatjava setup.
- Kept coatjava local to this repository so CLAS12 systems can use Java geometry services without polluting the
  GEMC runtime repository.

## Compatibility notes

- CLAS12 detector geometry ported from GEMC2 should use `g4placement_type = "passive"` in `GVolume`.
- Ordered rotations from CLAS12Tags should remain ordered in the database, for example `ordered: yxz, ...`.
- The obsolete DC `original` variation is intentionally not supported by the GEMC3 DC port.

## Validation

- DC default geometry is expected to token-match
  `../clas12Tags/geometry_source/dc/dc__geometry_default.txt` for shared GEMC geometry fields.
- The default DC geometry run is `11`.

## Documentation and validation updates

- Added README workflow badges for Test, Deploy, Sanitize, CodeQL, Doxygen, Binary Tarballs, and Nightly Dev
  Release.
- Added README guidance for comparing generated GEMC3 ASCII geometry against the CLAS12Tags reference files.
- Updated `scripts/compare_ascii_geometry.py` to compare semantic geometry records by volume name and report
  field-level differences with `--diff`.
