# CLAS12 GEMC Systems 0.2


<br/>

# Release notes

- Added the CLAS12 magnetic field plugin `gfieldclas12-cmag`, which evaluates the composite CLAS12
  solenoid + torus field through David Heddle's cMag library (the `clas12-cmag` subproject).
- The field is configured through the generic `gfields` YAML node with `type: clas12-cmag`; the plugin
  reads its solenoid/torus binary maps and placement parameters from the field definition.
- CLAS12 steering examples now define the field with explicit `solenoid`, `torus`,
  `solenoid_scale`, and `torus_scale` parameters and attach it with `global_field: clas12`.
- Field maps are downloaded to `<prefix>/fields` during `meson install` and read from the `fields`
  directory installed next to the plugin, so no `FIELD` / `FIELD_DIR` environment variable is needed
  at runtime.
- The EC digitization is now the shared `ecal` plugin: `gvolume.digitization = "ecal"` so the EC (and
  the future PCAL) system use a single `ecal.gplugin` and write the `ECAL::adc` / `ECAL::tdc` banks.
- Added an `ec` subsystem to `hipo-histos`. It reads `ECAL::adc` and `ECAL::tdc` and produces the
  per-component ADC and TDC distributions for the first EC layer as 6x6 matrices, plus a
  component-vs-layer occupancy map for each of the six sectors, with ROOT output and PNG/PDF plots.
- The HIPO streamer and CLAS12 cMag field plugins no longer add direct Geant4 or CLHEP link
  dependencies; they consume GEMC's plugin link metadata so macOS plugins do not record Geant4
  dynamic-library load commands.
- Added the FTOF (Forward Time-of-Flight) system: a coatjava-backed geometry builder under
  `geometry_src/ftof` and the `ftof` digitization plugin, the GEMC3 port of the clas12Tags
  `ftof_hitprocess`.
- The FTOF geometry publishes the panel-1a/1b/2 scintillator paddles, their air mother panels, and the
  lead shields for all six sectors, in the `default` and `rga_spring2018` variations.
- The FTOF digitization plugin (`ftof.gplugin`) splits each paddle hit into its Left and Right PMT
  readout channels and writes the `FTOF::adc` / `FTOF::tdc` banks with the attenuation, gain-matching,
  time-walk, and time-resolution model loaded from the `/calibration/ftof` CCDB tables.
- FTOF threshold and efficiency rejection are now opt-in through the GEMC core `-applyThresholds` /
  `-applyInefficiencies` options (default off), via the new plugin hooks `apply_thresholds_impl` /
  `apply_efficiency_impl`. By default every digitized hit is kept, matching the clas12Tags reference
  whose `APPLY_THRESHOLDS` / `DETECTOR_INEFFICIENCY` are off; this removes a per-hit deficit against the
  reference.
- DC, ECAL, and FTOF now keep threshold and efficiency policy code in dedicated
  `apply_thresholds.cc` / `apply_efficiency.cc` files. `digitize_hit.cc` only builds detector
  observables and caches deterministic transient intermediates; efficiency random draws are made in
  `apply_efficiency_impl`.
- Added the PCAL (Pre-shower Calorimeter) geometry under `geometry_src/pcal`: a coatjava-backed builder
  that reuses the shared `ecal` digitization plugin (`digitization: ecal`) and the `ECAL::adc` /
  `ECAL::tdc` banks, in the `default` and `rga_spring2018` variations.
- Added `ftof` and `pcal` subsystems to `hipo-histos`. The `ftof` subsystem reads `FTOF::adc` and
  `FTOF::tdc` and produces per-panel (1A/1B/2) and combined ADC and TDC spectra, a paddle-vs-panel
  hit-count map per sector, and a global true-hit y-vs-x map. The `pcal` subsystem reads the `ECAL`
  banks restricted to the PCAL hipo layers (1..3).
- Extended the `ec` `hipo-histos` subsystem with generated primary phi/theta plots and sector-summary
  diagnostics for generated primary phi, true EC-hit phi, and ADC row sector.
- DC digitization now obtains the configured magnetic field through the GEMC core
  `GMagneto::initialize_magnetic_field` field-probe helper instead of a plugin-local field initializer.
- Detector steering cards now use periodic per-event progress logging (`log_every`) and drop the manual
  `verbosity` blocks.
- The ASCII reference check also compares materials: `scripts/compare_ascii_databases.py` (renamed from
  `compare_ascii_geometry.py`) maps the GEMC2 and GEMC3 materials columns onto common fields and
  compares them by material name alongside the geometry comparison.
- Imported the LTCC CAD volumes (the aluminium support frame, nose hardware, and Winston cones `WC_*`)
  as `solid = CAD` rows in the same SQLite `ltcc` system as the native geometry, so the steering card
  needs only one `gsystem` entry. Their STL meshes, cured with pygemc's `utilities/cure_mesh.py`, live in
  `geometry_src/ltcc/stls/`; the Winston cones keep the `ltcc_AlMgF2` optical surface. Sector 3 supplies the
  mesh-backed frame, nose, and small/medium/large Winston-cone volumes. `copyOf` placements reuse them in
  every present sector and for cone segments 1-17 on both sides, following `ltcc_frame.pl` and `cones.pl`.
- The frame/nose bolt holes are filled with pygemc's new `utilities/remove_holes.py` so the plates are
  solid tessellated volumes; convex plates that must read as perfectly flat (e.g. `S1-TB`) are instead
  rebuilt from their outline as a clean extruded slab (holes gone entirely — see
  `geometry_src/ltcc/stls/notes.md`). To eliminate the mesh overlaps that led GEMC2 to disable these
  pieces, the interpenetrating CAD meshes are shrunk in place by 3-4% about their own centre; the pieces
  that still overlapped beyond that (`S1-LW`, the `Epoxy` light guide, and `S1-BW`, which clashes with
  the flattened `S1-TB`) are dropped. The result has **no overlaps between any CAD (STL) volumes**. A few
  complex brackets (`S1-BRB`, `FrontPlate`) keep a handful of non-manifold facets after hole filling,
  which Geant4 reports as non-fatal tessellated-solid warnings.
- The frame/nose meshes are decimated hard (~1000 facets each, cones ~1500) so the whole `stls`
  mesh set is ~13k facets (from ~62k at import; the placed scene dropped from ~250k). The entire mesh
  pipeline — cure, bolt-hole fill, manifold clean, per-piece in-place shrink, and the `S1-LW`/`Epoxy`
  drops — is reproducible with `geometry_src/ltcc/build_cad_meshes.py`.
- Note on visualization: slicing (cutaway) with the default `TOOLSSG_QT_GLES` viewer computes the cut
  on the CPU via `BooleanProcessor`, which stalls on tessellated (CAD) polyhedra. Use an OpenGL driver
  (e.g. `-g4view="[{driver: OGLIQt}]"`) to slice the LTCC CAD, where the cut is GPU-clipped.
- The LTCC elliptical mirror volumes use the GEMC 0.4 predefined `G4_AIR_Optical` material instead of
  redefining GEMC2's engine built-in `Air_Opt`. `LTCCPMTGlass` uses a 1 cm absorption length in GEMC2
  and GEMC3 so a photon entering the PMT window is treated as detected and dies in the glass.
- Every detector constants loader (DC, ECAL, FTOF, LTCC) now fails loudly on a CCDB problem instead of
  crashing or silently digitizing every hit to nothing: the shared `clas12ccdb::connect` helper catches
  the exception ccdb throws on a failed connection (returning a clean error rather than reaching
  `std::terminate`), and `clas12ccdb::loadTable` reports an empty or failed mandatory table.
- On macOS the ccdb subproject now links its MySQL client from the first installed of
  `mariadb-connector-c`, `mysql-client@8.4`, `mysql-client`, `mysql`. clasdb authenticates with
  `mysql_native_password`, which Oracle removed from the MySQL 9.x client library; the MariaDB connector
  (preferred) and the MySQL 8.4 LTS still provide it, so a from-scratch build connects to clasdb without
  a manual relink.

## Compatibility notes

- The EC system declares `digitization: ecal` in its gsystem YAML so GEMC's startup option/verbosity
  probe loads `ecal.gplugin` even though the gsystem is named `ec`. This relies on the GEMC gsystem
  `digitization` field; a GEMC build without it reports `Invalid verbosity or debug requested: ecal`.
- The FTOF system declares `digitization: ftof` and PCAL declares `digitization: ecal` in their gsystem
  YAML, so GEMC's startup option/verbosity probe loads the matching plugin (`ftof.gplugin` for FTOF, the
  shared `ecal.gplugin` for both EC and PCAL).
- Geant4-free macOS plugin load commands require a GEMC install whose `gemc.pc` advertises
  `plugin_link_args`. Older GEMC metadata still builds, but may keep Geant4 libraries in the plugin
  runtime dependency list.
- DC digitization requires the GEMC core `GMagneto::initialize_magnetic_field` helper introduced in GEMC
  0.4; an older GEMC core that still expects the plugin-local field initializer will not build the DC
  plugin.
- The detector plugins now require the GEMC 0.4 post-digitization policy API with mutable
  `GDigitizedData*` callback arguments, transient digitized-data variables, and intrinsic-policy hooks.

## Detailed list of changes and fixes

- Replaced the oversized axis-aligned LTCC gas mothers with fitted 25-degree G4Trap sectors. The new
  envelope contains the active native volumes and sector-3 CAD frame while clearing DC region 3 and PCAL.
- Added the root `generate_geometry.zsh` to generate a selectable list of subsystem geometries into one
  `experiments/gemc.sqlite` database or per-system ASCII output directories. Its explicit per-system STL
  directory map copies runtime meshes into `<system>/<stl-directory>` (currently `ltcc/stls`) beside the
  generated experiment geometry. The script installs the complete `experiments` directory under the Meson
  prefix configured in `build/`; `--prefix` overrides that location and `--no-install` only generates files.
- Coatjava-backed geometry scripts now detect a missing or incomplete local coatjava installation before
  launching Java and report the reset/reinstall command instead of exposing a Java class-loading traceback.
- Added the `gfieldclas12-cmag` field plugin under `plugins/field/`, the GEMC3 port of the clas12Tags
  `gclas12BinaryMappedField`. It loads the CLAS12 solenoid and torus binary maps through the cMag
  library and returns the composite field at a point.
- Linked the plugin against the `clas12-cmag` subproject (David Heddle's cMag C library), wrapping its
  headers in `extern "C"` so the C++ plugin uses the C symbols directly.
- Configured the field through the core GEMC generic `gfields` option node: `name` and `type` are
  schema keys and every other scalar key (solenoid/torus map names, scales, displacements, overall
  origin/rotation, interpolation) is forwarded verbatim to the plugin.
- Updated the DC steering card and README usage notes to use `type: clas12-cmag`, explicit
  solenoid/torus scales, and `global_field: clas12` so defining the cMag field also attaches it to
  the ROOT world volume.
- Resolved the field-map directory from the plugin's own on-disk location (`<plugin_dir>/../fields`)
  via `dladdr`, replacing the clas12Tags `FIELD` environment variable. An explicit `dir` parameter
  still overrides it.
- Added `meson/install_fields.py` and wired it as a `meson install` script so the CLAS12 binary and
  ascii field maps are downloaded to `<prefix>/fields` (idempotent; skips files that already exist).
- Loaded the cMag maps per worker thread, since the GEMC3 field registry is built per thread; this
  keeps cMag's mutable probe cells thread-safe.
- Converted cMag units (cm coordinates, kilogauss field) to Geant4 units on every field query, and
  applied the configured map origin offset and axis rotation to the returned field vector.
- Added the `hipo-histos` `ec` subsystem (`hipo-histos/ec/histos.{h,cc}`, `ECHistos` / `ECSubsystem`),
  reading `ECAL::adc` and `ECAL::tdc`; registered `ec` in `subsystems.cc`, the Meson build, the
  `--help` text, and the README.
- Booked 36 ADC and 36 TDC 1D histograms for the first EC layer (hipo layer 4) drawn as 6x6 component
  matrices, and six component-vs-layer occupancy `TH2D` maps (one per sector, normalized to percent),
  wired into the comparison and CI diagnostic paths.
- Set the EC volumes' `digitization` to `ecal` and renamed the plugin library, logger tag, options
  (`ecal_timeWindow`, `ecal_outputRAW`, `ecal_accountForHardwareStatus`), and verbosity key to `ecal`,
  so the EC and PCAL systems share one `ecal.gplugin`.
- Declared `digitization: ecal` in `geometry_src/ec/ec.yaml` so GEMC's startup probe registers the
  shared plugin's options and verbosity key before the digitization factory is instantiated.
- Switched the GEMC fallback dependency construction to query GEMC's installed `gemc.pc` through
  `pkg-config` for compile flags, link archives, and `plugin_link_args`, instead of parsing `Libs:`
  by hand and adding Geant4/CLHEP as explicit transitive plugin dependencies.
- Removed the explicit Geant4/CLHEP dependencies from `gfieldclas12-cmagFactory`; the HIPO streamer
  and cMag field plugins now rely on the native `gemc_dep` contract for host-provided symbols.
- Added `geometry_src/ftof/` (coatjava bridge, geometry builder, materials, variations, run card),
  mirroring the EC port. The builder runs `FTOFGeant4Factory` through the shared `CoatjavaFactory`,
  normalizes coatjava solid names (`Box`->`G4Box`, `Trd`->`G4Trd`), places volumes with the `passive`
  Geant4 constructor, and applies GEMC2 metadata by volume name: invisible air panel mothers
  (`ftof_p{1a,1b,2}_s{S}`), sensitive scintillator paddles (`panel{1a,1b,2}_sector{S}_paddle_{n}`,
  `digitization = ftof`, identity sector/panel/paddle/side), and `G4_Pb` shields
  (`ftof_shield_p{1a,2}_sector{S}`) for panels 1a and 2.
- Added the FTOF digitization plugin under `geometry_src/ftof/plugin/`, following the EC plugin layout
  (`readoutSpecs.cc`, `process_gtouchable.cc`, `calibration_constants.cc`, `load_tt.cc`,
  `digitize_hit.cc`). `processTouchableImpl` runs the base time-cell binning and then duplicates each
  touchable with the `side` identifier toggled to 1, reproducing the clas12Tags `processID` Left/Right
  PMT split; `digitizeHitImpl` ports `integrateDgt` (attenuation, PMT gain matching, Poisson p.e.
  fluctuation, constant/energy/position time walk, and time-resolution smearing) and emits
  `ADC_order`/`TDC_order` per PMT side. Registered `ftof` in the `clas12_systems` Meson list so the
  geometry test runs and `ftof.gplugin` is built and installed.
- Moved FTOF threshold/efficiency rejection out of `digitizeHitImpl` into the GEMC core post-digitization
  hooks `apply_thresholds_impl` (attenuated energy below the per-channel threshold) and
  `apply_efficiency_impl` (per-channel efficiency draw). These run only when `ftof` is listed in
  `-applyThresholds` / `-applyInefficiencies`, so the default run keeps every hit and matches the
  clas12Tags reference, which applies neither by default. Rejected hits also drop their `MC::True` row
  when `also_reject_true_info` is set.
- Split DC, ECAL, and FTOF policy hooks into dedicated callback files. DC stores the deterministic
  distance-dependent inefficiency inputs in transient digitized data and draws the intrinsic
  inefficiency random in `apply_efficiency_impl`. ECAL stores the unrounded ADC and discriminator time;
  its threshold hook can reject the hit, while its efficiency hook only suppresses `TDC_TDC` and keeps
  the ADC bank, matching clas12Tags. FTOF stores the attenuated deposited energy for its threshold hook
  and draws the optional efficiency random only in `apply_efficiency_impl`.
- Added `geometry_src/pcal/` (coatjava bridge, geometry builder, materials, variations, run card). The
  builder runs `PCALGeant4Factory` through the shared `CoatjavaFactory` and sets `digitization = ecal`,
  so the PCAL strips are digitized by the shared `ecal` plugin and written to the `ECAL` banks.
- Added the `hipo-histos` `ftof` subsystem (`hipo-histos/ftof/histos.{h,cc}`, `FTOFHistos` /
  `FTOFSubsystem`), reading `FTOF::adc`, `FTOF::tdc`, and `MC::True` (FTOF detector id 12). It books
  per-panel and combined ADC/TDC spectra (ADC 0..8000, TDC -6000..2000), a paddle-vs-panel hit-count
  `TH2D` per sector, and a global true-hit y-vs-x `TH2D`, all routed through the generic 1D and 2D
  comparison/diagnostic path.
- Added the `hipo-histos` `pcal` subsystem reading the `ECAL` banks restricted to PCAL hipo layers 1..3,
  with summed ADC/TDC spectra per U/V/W view and combined, per-sector component-vs-layer hit-count maps,
  and a global true-hit XY map.
- Registered `ftof` and `pcal` in `hipo-histos/subsystems.cc`, the Meson source list, the `--help`
  supported-systems text, and the README; added both to the `hipo_histos_compare.yml` CI matrix.
- Extended the EC `hipo-histos` subsystem with generated primary phi/theta histograms and sector-summary
  diagnostics (generated primary phi, true EC-hit phi, ADC row sector), wired into the comparison and
  diagnostic paths.
- Replaced the DC plugin-local `initialize_magnetic_field` / `magnetic_field_magnitude_tesla` helpers
  with a call to the GEMC core `GMagneto::initialize_magnetic_field(gopts, fieldPolarity, log)`, so the
  DC digitization shares the core field-probe logic.
- Switched the DC and EC steering cards to `log_every: 100-0` periodic progress logging and removed the
  manual `verbosity` blocks.
- Renamed `scripts/compare_ascii_geometry.py` to `scripts/compare_ascii_databases.py` and extended it to
  the materials databases: the clas12Tags 23-column and pygemc 18-column materials rows map onto common
  fields (density, ncomponents — derived from the composition pair count on the pygemc side —
  components, the optical and scintillation properties, and the mie fields, which pygemc does not store
  and therefore reports if a reference material sets them). Numeric tokens canonicalize to the shortest
  round-trip float (perl drops trailing zeros, pygemc keeps raw source strings) and the clas12Tags
  `none`/`-1` and pygemc `NULL` empty markers unify, so only real value differences are reported. The
  materials comparison is skipped for systems that ship no materials files.
- Added `MATERIAL_NAME_MAP` to the comparison (mirroring `SOLID_NAME_MAP`) translating GEMC2 engine
  built-in material names onto their gemc3 predefined names (`Air_Opt` -> `G4_AIR_Optical`), and
  `MATERIAL_FIELD_EXCEPTIONS` listing accepted intentional differences per material and field
  (currently `LTCCPMTGlass.absorptionLength`).
- Removed the local `Air_Opt` definition from `geometry_src/ltcc/materials.py`; the elliptical mirror
  volumes now set `material = "G4_AIR_Optical"`, the gemc3 predefined equivalent (including the
  RINDEX 1.00 optical property GEMC2 attached to its built-in).
- Gave `LTCCPMTGlass` a finite absorption length (300 cm across the photon-energy grid, the fused-silica
  scale): GEMC2 defined none and relied on its 100-step optical-photon kill, so a photon trapped in the
  window by total internal reflection could only be stopped by the step guard. The ~cm direct window
  path keeps >99% transmission, leaving the photo-electron yield essentially unchanged.
- Added `geometry_src/clas12_ccdb.h`, a shared header (on every plugin's include path via the new
  `clas12_common_inc` in `meson.build`) providing `clas12ccdb::connect(conn, log)` and
  `clas12ccdb::loadTable(calib, table, data, log)`. `connect` wraps
  `ccdb::CalibrationGenerator::CreateCalibration` in a `try/catch`: ccdb throws `std::logic_error` when
  the connection fails (bad `CCDB_CONNECTION`, unreachable host, or a MySQL client library that cannot
  authenticate to the server), and left uncaught it reached `std::terminate` and aborted the process;
  the helper now logs the connection error and returns nullptr so the plugin returns `false`. `loadTable`
  clears the row buffer, fetches one CCDB table (also inside a `try/catch`), and on a query error or an
  empty result logs a warning naming the table and returns `false`. The DC, ECAL, FTOF, and LTCC
  `loadConstantsImpl` now open the connection through `connect` and load every mandatory table through
  `loadTable`, returning `false` on any failure so the event dispenser aborts the run with a clear
  message. Previously an empty table (for example when `CCDB_CONNECTION` points at something that is
  not a CLAS12 CCDB, or a run/variation with no entry) left the constants at their defaults so
  digitization silently dropped every hit — and for the DC/ECAL tables read as `data[0][...]`, the
  access on the empty vector was undefined behavior. DC's `/geometry/dc/superlayer` read through
  `GetAssignment` (a separate ccdb call, not `GetCalib`) is guarded inline the same way. Optional tables
  guarded by `accountForHardwareStatus` keep the plain fetch, since an empty status set is acceptable.
- `meson/meson.build` selects the ccdb MySQL connector (`MYSQL_DIR`) from the first installed of
  `mariadb-connector-c`, `mysql-client@8.4`, `mysql-client`, `mysql`, preferring connectors that still
  ship `mysql_native_password` (which clasdb requires and MySQL 9.x dropped) so a clean build links a
  working client without a post-build `install_name_tool` relink.
- The ccdb subproject is patched via the wrap (`subprojects/ccdb.wrap` `diff_files` →
  `subprojects/packagefiles/ccdb_ssl_no_enforce.patch`) so that, when built against `mariadb-connector-c`,
  `MySQLDataProvider::Connect` does not enforce TLS (`MYSQL_OPT_SSL_ENFORCE` /
  `MYSQL_OPT_SSL_VERIFY_SERVER_CERT` off). MariaDB enforces TLS by default and clasdb has no SSL, so
  without this the connection fails with `Error 2026`. The patch is guarded with `#ifdef LIBMARIADB`, so
  it is a no-op for the Oracle clients (which removed the option and do not enforce TLS). With both the
  connector selection and this patch, a clean build connects to clasdb through MariaDB.
- Preserved Unix line endings for the CCDB patch metadata and the upstream CRLF line endings for its hunk,
  allowing Meson to apply the patch with either its POSIX `patch` command or its `git apply` fallback.
- Added the LTCC `hipo-histos` subsystem (`hipo-histos/ltcc/histos.{h,cc}`, `LTCCHistos` /
  `LTCCSubsystem`), reading `LTCC::adc`, `LTCC::tdc`, and `MC::True` (LTCC detector id 16). It books
  per-half-sector and combined ADC/TDC spectra, a PMT-segment-vs-half-sector hit-count map per sector, a
  global true-hit XY map, and a true-hit-time spectrum, wired into the comparison and diagnostic paths and
  registered in `subsystems.cc`, the Meson source list, and the `--help` supported-systems text.
