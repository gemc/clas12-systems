# CLAS12 GEMC Systems Release 0.4

Upcoming in the next release. Changes since `0.3`.

This version includes:

- CLAS12 beamline geometry with optimized CAD meshes.

<br/>

# Release notes

- Imported all fifteen native beamline variations and their materials from GEMC2. The beamline is passive
  and needs no sensitive digitization plugin. Separate CAD systems preserve the run-specific placements and
  all three transverse-magnet alternatives. Selected CAD meshes have reduced triangulations while retaining
  their materials and placements; the remaining meshes retain their engineering tessellation.

<br/>

## Documentation

- Documented the DRelease-based nightly workflow, automatic tag-date notes, and publication settings.
- Added beamline generation and steering instructions, run mappings, and the retained raw-mesh warnings.

<br/>

## Tests

- Added agent-free CI checks for generated plugin catalogs using the shared GEMC validator. Invalid structure
  fails before the build matrix; missing messages report coverage and retain English fallback.

- Registered beamline generation and GEMC construction tests, and extended the semantic comparator to check
  both beamline CAD companions against the original GXML placements.
- Replaced duplicated nightly release steps with `gemc/DRelease@v1`, using full Git history and
  commits after the latest version tag's date instead of a fixed start date. Publication is serialized,
  and notes are generated in the runner's temporary directory before updating the `dev` tag.
  Retained the release title and existing release assets.

<br/>

## Dependencies

- CI installs Qt 6 Linguist tools and translation data for the multilingual GEMC source dependency.

<br/>

## Compatibility notes

- Regenerate beamline SQLite databases and use `default` for every beamline system; select configurations
  through `runno`. Transverse alternatives now use runs 10000204, 10000206, and 10000207.

- Custom beamline CAD placements must use `moller_cone` in place of `main-cone`.

- Custom beamline CAD placements must use `FTInnerShield` in place of `taggerInnerShield`.

- Custom beamline CAD placements must use `FTOuterMount` in place of `outerMount` to match the STL.

- Custom beamline CAD placements must use `FTOuterFlange` in place of `outerFlange` to match the STL.

- Custom beamline CAD placements must rename `nut1`--`nut9` to
  `FTInnerShieldAndFlange_Bolt1`--`FTInnerShieldAndFlange_Bolt9` to match the new mesh stems.

- Custom beamline CAD placements must use `FTInnerShieldAndFlange` in place of `innerShieldAndFlange`
  to match the renamed STL.

- Custom beamline CAD placements must replace `adjuster1`, `adjuster2`, and `adjuster3` with one
  `ft_adjuster` row using their common material, position, and rotation.

- Custom beamline CAD placements must use `Beamline_Adapter_1` in place of
  `Torus_Beam_Tube_Reducer_2` to match the renamed adapter STL.

## Detailed list of changes and fixes
- Qualify collected SQLite CAD mesh paths with their detector directory so beamline and HTCC meshes
  resolve from the generated and installed experiments directories.

- Cleared FT and Moller cone CAD interface overlaps with local reliefs in five meshes, retaining the
  shield, flange, tip, placements, and materials; recorded geometry checks and tracking benchmarks.

- Renamed the Moller-cone extension tungsten add-on in four runs and restored its missing radial-port
  wall without capping the passages, and reduced it to 12,000 triangles with protected features.
  Recorded separate raw-input and closed-reference tracking benchmarks and retained assembly warnings.

- Renamed and optimized the Moller cone extension lead fill and casing in four run configurations,
  preserving inner interfaces and openings; recorded repeated tracking measurements and assembly checks.

- Renamed the inner Moller-cone extension in four run configurations, restored its missing radial-port
  wall without capping the passages, and reduced it to 12,500 triangles with protected features.
  Recorded separate raw-input and closed-reference tracking benchmarks and retained assembly warnings.

- Renamed the beamline flange assembly to `FTFlange` in four run configurations and reduced its
  already-coarse mesh from 552 to 540 triangles with retained opening, face planes, and bounds.
  Repeated tracking measurements show no meaningful gain; existing assembly defects remain.

- Renamed the Moller cone tip in four run configurations and reduced its mesh to 5,000 triangles,
  retaining sharp faces, openings, bounds, and tungsten volume within 0.0005%; recorded isolated
  tracking speedups and the pre-existing cone/tip overlap separately.

- Store all beamline geometry and materials under `default`, indexed by run, so changing `-runno` loads
  the corresponding configuration. Give transverse CAD alternatives distinct custom runs and check every
  beamline run in the GEMC construction test, including the reported empty run 16000.

- Relieved both downstream Segment 1 sockets to clear the adapter and Segment 2 while preserving
  placements and neighboring meshes; verified clean assembly and full default construction.
- Recorded the downstream socket material change and repeated three-part tracking comparison.

- Renamed and optimized the Moller cone to 5,000 triangles, filled its surface holes, and widened
  its entrance counterbore to clear the unchanged FT inner shield in every placement.
- Recorded independent cone/shield clearance, material changes, and repeated raw-input and
  repaired-reference tracking comparisons in the CAD optimization note.

- Rebuilt and simplified the renamed FT inner shield to 6,500 triangles, closing flange and tube
  holes and all flange recesses while retaining its longitudinal grooves. Added separate upgrade
  and smooth-reference tracking comparisons and recorded the material changes and uncertainty.

- Renamed and simplified the FT outer mount to 2,740 triangles, repairing four missing faces and
  protecting a relieved flange joint; retained its openings and placements and added clearance checks.

- Added an outer-flange benchmark control that compares the hole-filled reference and simplified mesh
  at fixed material volume, with separate repeated tracking results retained in the CAD optimization note.

- Renamed the FT outer flange and reduced it to 836 triangles by filling twelve bolt tunnels and
  retriangulating its flat annulus with exact rim coordinates; recorded the 8.296635% material increase.

- Replaced nine FT inner-shield threaded bolts with 192-triangle smooth shafts and simplified heads,
  matching each copper volume within 0.0001% and leaving 0.15 mm at the shield blind-hole end faces.

- Renamed the FT inner shield and flange and reduced its mesh to 22,000 triangles with unchanged bounds,
  topology, alloy material, and placement; protected its enclosed pocket and added isolated benchmarks.

- Unified the FT adjuster trio into a 48-triangle solid matched to its sealed reference union volume;
  retained the common material and placement, archived the originals, and added matched benchmarks.

- Renamed the beamline reducer to `Beamline_Adapter_1` and conservatively reduced the adapter and exit
  casing to 526 and 1,384 triangles; protected casing mating faces and retained the coarse lead fill exactly.
- Extended the offline beamline benchmark to the three-volume adapter and exit-shield group.

- Repaired the downstream tube's seven missing annular joins without capping its bore, and reduced the
  two downstream STL meshes to 5,000 and 600 triangles with retained names, materials, and placements.
- Extended the offline beamline benchmark to select the downstream pair and its forward acceptance.
- Renamed the apex hub to `Apex_Shield_Hub` in every CAD variation, halved the lead-fill triangle count,
  and reduced the hub from 36,354 to 20,000 triangles with protected sharp features and mesh-quality checks.
- Added a reproducible apex mesh builder and an offline benchmark for loading, peak memory, matched
  electron/hadron transport, and separate overlap diagnostics.
- Resolve the shared beamline run constants during direct script execution without the build venv's path setup.
- Prefer static dependencies in parent builds so the GEMC subproject links CLHEP and Geant4 archives
  instead of shared libraries that cannot be found after installation on macOS.
- Install or update pygemc and its command-line tools under `python_env` when using an installed GEMC,
  matching the standalone GEMC installation layout.
- Migrated detector, CCDB, HIPO, and magnetic-field logging to the complete-message GEMC logger API;
  plugins must be rebuilt against matching GEMC headers.
- Added a generated English plugin message catalog and source manifest, using the shared GEMC
  extractor and placeholder validator.
- Install plugin language catalogs in their own domain for automatic GEMC runtime discovery,
  including through existing plugin paths. Rebuild plugins for the updated logger layout.
- Enabled plugin catalog generation in the shared agent translation manifest and weekday job,
  with Codex review, local placeholder checks, atomic batch checkpoints, and source commit tracking.
